# UEAgentCraft Backend v0.2.0

Date: 2026-05-21

This release focuses on editor operation reliability, Blueprint graph automation
diagnostics, and public project documentation. The backend remains local-first:
write operations are still Proposal-based and must be executed by UEAgentTool
after user confirmation.

## Highlights

- Expanded the Editor Operation Bridge into a grouped capability catalog across
  assets, Blueprints, UMG, level actors, and Material Instances.
- Added Blueprint Graph operation smoke coverage for whitelisted node templates,
  explicit pin connections, Blueprint compile proposals, and guardrail failures.
- Added Agent Chat -> Editor Operation smoke coverage for common natural
  language requests.
- Added result diagnostics for Blueprint graph execution, including missing
  created nodes, missing linked pins, missing compile status, compile failure,
  and missing dirty packages.
- Added deterministic repair advice for Blueprint graph operation results.
- Added follow-up candidate generation for selected repair advice, while keeping
  follow-up execution disabled by default.
- Added editor operation health summary endpoints for real-editor smoke review.
- Added generated public editor operation catalog, demo checklist, FAQ, and
  clearer README / CONTRIBUTING guidance.
- Added non-executable roadmap metadata for upcoming UMG, Material, and Level
  operation tracks.
- Extended Project Inventory snapshots with optional `level_actors` and
  `material_instances` fields, plus read-only query endpoints for richer
  current-project facts.
- Added a read-only Project Inventory Blueprint projection endpoint for
  parent class, component, variable, function, graph, and interface summaries.
- Extended Project Inventory Blueprint facts with optional `graph_summaries`
  so Agent Chat can ground Blueprint graph/node questions in UE-collected
  project facts.
- Added a focused read-only `/project-inventory/blueprint-graphs` endpoint for
  graph/node/pin summaries collected from Project Inventory.
- Added a deterministic Project Inventory chat smoke script proving Agent Chat
  can answer Blueprint graph/node questions from saved `graph_summaries`.
- Improved Agent Chat inventory grounding for current-level object questions
  and Material Instance parameter-value questions, including deterministic
  summaries when the live LLM is unavailable.
- Promoted `inspect_level_actors` and
  `inspect_material_instance_parameters` from roadmap metadata to backend
  read-only inspection APIs backed by Project Inventory.
- Added `set_material_instance_static_switch`, a confirmed-write Material
  Instance static switch proposal and UEAgentTool executor.
- Added `set_actor_metadata`, a confirmed-write Level Actor label/folder/tags
  proposal and UEAgentTool executor.
- Added `set_umg_widget_appearance`, a confirmed-write UMG opacity/enabled
  state/TextBlock color/font-size proposal and UEAgentTool executor.
- Added `set_umg_widget_brush`, a confirmed-write UMG Image/Border Brush
  texture/material proposal and UEAgentTool executor.
- Added `set_umg_slot_layout_v2`, a confirmed-write UMG HorizontalBox,
  VerticalBox, and Overlay slot-layout proposal and UEAgentTool executor.
- Added `arrange_actors_pattern`, a confirmed-write Level Actor arrangement
  proposal and UEAgentTool executor for simple line, grid, and circle layouts.
- Added a Tool Registry manifest endpoint that exports `ToolSpec` entries in an
  MCP-compatible metadata shape while keeping confirmed-write tools Proposal-only.
- Added a Tool Registry Proposal Bridge that maps confirmed-write `tool_id`
  calls to pending editor-operation Proposals without executing UE writes.
- Added a plan-only multi-step editor workflow planner that emits Proposal
  request hints without auto-executing any UE writes.
- Added a workflow template discovery endpoint so tools or UI can inspect
  supported plan-only workflow types before asking for a plan.
- Integrated the workflow planner into Agent Chat for explicit multi-step
  requests while preserving single-step Proposal routing.
- Added workflow quick actions in Agent Chat responses so ready plan steps can
  be shown as "Create Proposal" actions without automatic execution.
- Added workflow step materialization so one ready workflow step can become a
  pending editor-operation Proposal without auto-executing the full plan.
- Extended the Blueprint print-then-compile workflow template so delay requests
  can plan `delay_print_string` before the compile step.
- Added follow-up candidate materialization so Blueprint graph repair candidates
  can become pending Proposals without automatic retry.
- Added editor-operation result quick actions so ready repair candidates can be
  surfaced in User View immediately after UEAgentTool reports execution results.
- Added a deterministic workflow materialization smoke script covering
  normal workflow-step, delay workflow-step, and follow-up-candidate Proposal
  conversion.
- Extended the Blueprint graph operation smoke script to cover result-time graph
  diagnostics, User View graph details, and follow-up quick-action generation.
- Added `delay_print_string`, a safe Blueprint node-template proposal for
  `BeginPlay -> Delay -> PrintString`.
- Improved Agent Chat planning for simple Blueprint `Print String` requests:
  EventGraph-targeted requests now default to `entry_event=BeginPlay`, while
  explicit unconnected requests remain unlinked.
- Hardened Agent Chat editor-operation routing for mixed Chinese/English
  Blueprint requests with `BP_ProjectSpecificName`, and prevented Blueprint
  names containing `Name` from being
  misclassified as Actor metadata edits.

## Editor Operation Safety

The safety model is unchanged:

- The backend creates confirmed-write Proposals.
- The UE plugin executes Unreal Editor APIs only after user confirmation.
- Follow-up candidates are drafts, not automatic actions.
- The backend does not auto-save packages.
- LLM output never directly executes editor writes.

## UE Frontend Impact

No mandatory UE frontend change is required for this release.

Optional enhancements:

- Group tools by `items[].group` from `/editor-operations/capabilities`.
- Display planned capabilities from `roadmap_items[]` as disabled/future items,
  not executable actions.
- Display `result_contract_fields` in Debug View.
- Show `repair_advice.actions[].title` and `next_step` in operation history.
- Let users opt into a follow-up candidate by explicitly creating a new
  Proposal from `create_request_hint`.
- UEAgentTool should submit `level_actors[]` and `material_instances[]` in
  Project Inventory snapshots so Agent Chat can answer current-level Actor or
  Material Instance parameter questions.
- No additional frontend API change is required for the improved natural
  language routing; the backend consumes the same snapshot fields.
- UEAgentTool now includes `set_actor_metadata`; users can confirm label,
  folder, or tag updates for one level Actor at a time.
- UEAgentTool now includes `set_umg_widget_appearance`; users can confirm
  opacity/enabled updates for one widget or TextBlock color/font-size updates.
- UEAgentTool now includes `set_umg_widget_brush`; users can confirm one
  Image or Border Brush texture/material update.
- UEAgentTool now includes `set_umg_slot_layout_v2`; users can confirm one
  HorizontalBox/VerticalBox/Overlay slot layout update.
- UEAgentTool now includes `arrange_actors_pattern`; users can confirm a simple
  line/grid/circle location arrangement for 2 to 12 existing Level Actors.
- No UEAgentTool change is required for `/api/v1/mcp/tool-registry/manifest`;
  it is backend metadata for future tool panels or MCP-compatible adapters.
- No UEAgentTool change is required for `/api/v1/mcp/tool-registry/proposals`;
  it creates the same pending Proposal shape that existing Proposal cards use.
- No UEAgentTool change is required for `/editor-operations/workflows/plan`;
  it returns plan-only Proposal request hints for optional future Workflow UI.
- No UEAgentTool change is required for Agent Chat workflow plans; they are
  read-only plan output. Ready steps also appear in `user_view.quick_actions`;
  those actions only create one pending Proposal and reuse existing Proposal
  cards when the user submits an individual step. Updated UEAgentTool builds can
  wire this quick action directly to the workflow step materialization endpoint.
- No UEAgentTool change is required for workflow step materialization; it
  creates the same pending Proposal shape as the existing editor-operation API.
- No UEAgentTool change is required for follow-up materialization; it only
  converts one ready repair candidate into the existing pending Proposal shape.
  Updated UEAgentTool builds can also surface result-time follow-up quick
  actions after `/editor-operations/results` returns.
- Updated UEAgentTool builds now report richer Blueprint Graph result
  observability for `add_blueprint_node_template` and `connect_blueprint_nodes`:
  stable node ids, pin ids, structured `created_nodes[]`, structured
  `linked_pins[]`, and display-only `linked_pin_summaries[]`. The backend
  remains backward compatible with older string-only result arrays and uses
  stable ids first when creating follow-up repair proposals.
- Result-time User View can also include
  `block_type=editor_operation_graph_details`, a display-friendly Blueprint
  graph details block containing stable node and pin ids for manual inspection
  or follow-up repair proposal creation.
